# 02 — 退出停止播放与重开自动恢复

**What to build:** 按 Back 退出播放页（Activity finish）后，ExoPlayer 仍在后台继续播放（进程被前台服务保活，无暂停逻辑，会一直出声）。需求：**退出即停止播放**；重新打开 App 时**自动恢复到上次频道播放**（用户已确认此交互）。

**Blocked by:** —

**Status:** resolved

## 设计要点

- `PlayerController` 新增公开 `stop()`：等价于现有私有 `stopPlayback()`（cancel retryJob、`player.stop()`、`currentChannelId = null`、state = Idle）。
- `PlayerController` 新增公开恢复入口（如 `resumeIfIdle()` 或类似）：**仅当** `state == Idle && channels 非空` 时重新触发 autoStart 逻辑（读 `lastChannelStore` 上次频道，不存在播第一个）。注意 `autoPlayStarted` 标志在进程存活期间不会重置，直接复用 `autoStart` 前的分支不会再次触发，必须显式调用。
- 竞态注意：首次冷启动时 `channels` 可能尚未从 Room 发射（empty），此时 `resumeIfIdle` 必须静默跳过——后续由 `PlayerController.start()` 的流发射走既有 autoStart 路径，保证不双播、不漏播。
- `MainActivity`：`onDestroy` → `playerController.stop()`；`onStart` → `playerController.resumeIfIdle()`（Activity 重建时单例 controller 保留了缓存的 channels，`onStart` 早于流发射即可恢复）。
- ServerService 不受影响：退出停止播放后内嵌 HTTP 服务继续运行（WebUI 后台可用），这是预期行为，不要动服务逻辑。

## 涉及文件

- `app/src/main/java/icu/gxb/hypertv/MainActivity.kt`（onDestroy / onStart 生命周期钩子）
- `app/src/test/java/icu/gxb/hypertv/player/PlayerControllerTest.kt`（新增 stop 后 Idle、resume 恢复播放、channels 为空时 resume 跳过等用例）

## 验收标准

- [ ] 播放中按 Back 退出 App → 播放停止，无后台出声（`player.stop()` 被调用）
- [ ] 重新打开 App → 自动恢复播放上次频道
- [ ] 首次冷启动不双播、不漏播（resume 竞态处理正确）
- [ ] 单测新增并通过；全量 `testDebugUnitTest` 绿（基线 221 个）

## Answer

**实现要点**

- `PlayerController` 新增公开 `fun stop()`：等价于私有 `stopPlayback()`（cancel retryJob、`player.stop()`、`currentChannelId = null`、state = Idle）。
- `PlayerController` 新增公开 `fun resumeIfIdle()`：仅当 `state == Idle && channels 非空` 时以 `scope.launch` 包装重新触发 `autoStart`（读 lastChannelStore 上次频道，不存在播第一个）。冷启动时 channels 尚未发射（empty）会静默跳过，由 `start()` 流发射走既有 autoStart 路径；播放中调用同样跳过。
- `MainActivity`：`onDestroy` → `playerController.stop()`；`onStart` → `playerController.resumeIfIdle()`。
- ServerService / HypertvServer 未改动：退出停止播放后内嵌 HTTP 服务继续运行，符合预期。
