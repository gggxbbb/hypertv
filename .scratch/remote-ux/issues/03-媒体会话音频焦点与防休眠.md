# 03 — MediaSession + 音频焦点 + 防休眠

**What to build:** 三个目标：① 系统知道 App 正在播放媒体（Android TV 据此抑制屏保/idle 判定）；② 防止与其他软件同时播放出声（音频焦点）；③ 播放页窗口防休眠/屏保。方案（用户已确认）：**media3-session 的 MediaSession 包住 ExoPlayer + AudioFocus 管理 + FLAG_KEEP_SCREEN_ON**，不引入新的前台服务/权限/通知。

**Blocked by:** 02 — 退出停止播放与重开恢复（退出停止后需释放音频焦点，接口语义以 02 的 `PlayerController.stop()` 为准）

**Status:** resolved

## 设计要点

### MediaSession
- 依赖：`gradle/libs.versions.toml` 加 `androidx-media3-session = { group = "androidx.media3", name = "media3-session", version.ref = "media3" }`（版本 1.11.0 与其他 media3 库一致），`app/build.gradle.kts` 加 `implementation(libs.androidx.media3.session)`。
- `@Singleton` 提供 `MediaSession`（包住注入的单一 ExoPlayer，ADR-0006 同实例），`setActive(true)`；应用进程终结时 `release()`。
- 可选：`PlaybackState` 元数据携带当前频道名/台标（帮助系统媒体卡片展示；如时间成本高可只做播放状态）。
- 不需要 `MediaSessionService`（用户已选轻量方案；Android 13+ 媒体卡片非本需求验收项）。

### AudioFocus（防同播）
- 新建独立控制器（如 `player/AudioFocusController.kt`，@Singleton，注入 ExoPlayer + Context + 可注入的 AudioManager 以利测试）。
- 通过 `Player.Listener.onIsPlayingChanged` 解耦播放时机：开始播放（isPlaying=true）→ `requestAudioFocus(AUDIOFOCUS_GAIN)`；停止（isPlaying=false 且 playbackState == IDLE，即 ticket 02 的 stop 路径）→ `abandonAudioFocus()`。
- 焦点回调：`AUDIOFOCUS_LOSS` / `AUDIOFOCUS_LOSS_TRANSIENT` → `player.pause()`（直播流暂停画面，可接受）；`AUDIOFOCUS_GAIN` → `player.play()`（TRANSIENT 恢复）。LOSS（永久）后不自动恢复。注意暂停/恢复绕过 PlayerController 状态机是已知取舍（频道名浮层/换台逻辑不受影响，换台会重新 setMediaItem+prepare+play 并重新请求焦点），在代码注释中说明。
- 决策逻辑（何时 request/abandon、各焦点事件的反应）抽成可单测的纯函数或可注入接口，AudioManager 用 Robolectric 或 fake 覆盖。

### KEEP_SCREEN_ON（防休眠/屏保）
- `MainActivity.onCreate` 窗口 `addFlags(WindowManager.LayoutParams.FLAG_KEEP_SCREEN_ON)`（无需权限）。

### Manifest
- 无新权限、无新服务声明。`media3-session` 是纯库依赖。

## Answer

**实现要点**
- **MediaSession**（目标①）：`PlayerModule` @Singleton 提供 `MediaSession.Builder(context, exoPlayer).build()`。media3-session 1.11.0 已移除 `setActive/isActive`——MediaSession 构造即 active、`release()` 后 inactive，代码注释已说明。isPlaying 由 ExoPlayer 自动同步到 session，系统据此抑制屏保/idle。release 挂靠 `HyperTvApplication.onTerminate`（仅模拟器触发，生产由进程终结回收）。未用 MediaSessionService，无新权限/前台服务/通知。
- **音频焦点**（目标②）：新增 `AudioFocusPolicy`（纯决策状态机：isPlaying=true→请求 AUDIOFOCUS_GAIN；isPlaying=false 且 STATE_IDLE→释放并清"待恢复"标记；LOSS/LOSS_TRANSIENT→暂停；GAIN→仅 TRANSIENT 后恢复；LOSS 永久不自动恢复；CAN_DUCK 忽略）+ `AudioFocusController`（@Singleton，注入 ExoPlayer+AudioManager，`Player.Listener.onIsPlayingChanged/onPlaybackStateChanged` 双回调同步、policy 幂等）。焦点丢失暂停/恢复绕过 PlayerController 状态机为已知取舍（换台会重走 setMediaItem+prepare+play 并重新请求焦点）。
- **防休眠**（目标③）：`MainActivity.onCreate` 加 `window.addFlags(FLAG_KEEP_SCREEN_ON)`。
- Manifest 未动。

**改动文件**
- `gradle/libs.versions.toml`、`app/build.gradle.kts`：新增 `androidx-media3-session`
- `player/PlayerModule.kt`：装配 MediaSession 与 AudioFocusController（注入 `context.getSystemService(AudioManager)`）
- 新增 `player/AudioFocusPolicy.kt`、`player/AudioFocusController.kt`
- `MainActivity.kt`、`HyperTvApplication.kt`（onTerminate release MediaSession）
- 新增测试 `AudioFocusPolicyTest`（12 例）、`AudioFocusControllerTest`（5 例，Robolectric+真实 ExoPlayer+本地静音 mp3，等待 READY 消除加载竞态）

**测试结果**
- `./gradlew testDebugUnitTest` 全绿：344 个（基线 327 + 新增 17），0 失败。
- Policy 覆盖：播放→请求、停止→释放、LOSS→暂停、TRANSIENT→暂停、GAIN→恢复、LOSS 不自动恢复、TRANSIENT 暂停后停止清除待恢复、CAN_DUCK 忽略等。

**真机验证项（尚未真机）**
1. 播放时系统媒体控制台/媒体卡片可见本 App 播放状态；TV 屏保不触发
2. 播放中打开其他出声 App（或遥控器启动另一媒体 App）→ 本 App 暂停；对方退出 → 本 App 恢复
3. 退出播放页（back 键）→ 焦点释放，其他 App 可正常出声
4. 播放页长时间停留无休眠/屏保
5. 直播换台期间焦点行为正常（重新请求）
